# План реализации добавления задач из календаря

## Цель и границы

Позволить создать задачу прямо из календаря дат, выбрав день в месячной сетке. Выбранная дата сразу подставляется в новую задачу. Сценарий должен работать и на компьютере, и на телефоне, не мешая открытию существующих задач и перетаскиванию задач между датами.

Функция использует существующий поток создания задачи и его поля. Новые сущности и изменения схемы базы данных не нужны, если текущий API уже принимает срок задачи.

## Предлагаемый UI и поведение

- Нажатие на свободное место ячейки дня открывает форму «Новая задача» с уже выбранной датой.
- Для мыши свободным местом считается область ячейки вне карточек задач. Клик по карточке сохраняет текущее поведение открытия задачи.
- В шапке ячейки добавить компактное действие «+» с доступным названием «Добавить задачу на [дата]». Оно даёт явную точку входа и остаётся удобным на узких экранах.
- На телефоне нажатие по пустой области ячейки также открывает ту же форму; отдельная кнопка «+» обеспечивает понятную подсказку о возможности добавления.
- Форма создаёт задачу с выбранным днём в локальной календарной дате пользователя. После успешного сохранения задача появляется в этой ячейке; при отмене ничего не создаётся.
- Если календарь показывает дни соседних месяцев, добавление из такой ячейки использует именно отображаемую дату, а не текущий месяц.
- Учитывать текущий контекст приложения (Inbox или проект), если действующий поток создания задачи уже поддерживает его. Не добавлять специальный выбор проекта без необходимости.

## Этапы реализации

### 1. Изучить существующие потоки

- Найти компонент месячного календаря `/dates`, обработчики кликов по ячейкам и карточкам, а также текущую форму/диалог создания задачи.
- Проверить формат даты, преобразование локальной календарной даты в API-значение и поведение на границах часового пояса.
- Проверить, как создание задачи обновляет TanStack Query кэш и как календарь получает список задач.
- Зафиксировать доступные контексты создания: Inbox, проект и секция.

### 2. Определить контракт открытия формы

- Передавать в общий поток создания задачи начальную дату и текущий контекст размещения.
- Начальное значение даты должно быть локальным днём, соответствующим выбранной ячейке; избегать сдвига на предыдущий/следующий день при сериализации.
- После сохранения закрывать форму и обновлять календарь тем же оптимистичным или серверным путём, что используется для создания задачи в других местах.
- При ошибке сохранить введённые поля и выбранную дату, чтобы пользователь мог повторить отправку.

### 3. Добавить взаимодействие с ячейкой

- Добавить обработчик выбора свободной области ячейки и отдельную кнопку добавления.
- Не открывать форму при клике/тапе на карточку задачи, ссылку, кнопку или элемент управления внутри ячейки.
- Сохранить перетаскивание задач между днями; начало drag не должно случайно открывать форму.
- Для доступности сделать действие добавления доступным с клавиатуры, добавить видимый focus state и понятный `aria-label` с датой.
- Проверить touch-поведение: короткий тап открывает форму; drag карточки по-прежнему меняет дату.

### 4. Проверки интерфейса

- UI-тест: действие «+» открывает форму и передаёт дату выбранного дня.
- UI-тест: клик по свободному месту открывает форму, а клик по задаче открывает её детали без запуска создания.
- UI-тест: дни соседних месяцев передают собственную дату.
- UI-тест: успешное создание показывает задачу в нужном дне; отмена не создаёт задачу; ошибка сохраняет черновик.
- Проверить даты около полуночи и перехода месяца на локальном времени пользователя.

### 5. Сквозные сценарии и документация

- Добавить Playwright-сценарий: открыть `/dates` в режиме Calendar, выбрать день, создать задачу и проверить её отображение после обновления страницы.
- Проверить создание из дня соседнего месяца и открытие существующей задачи из карточки.
- Проверить мобильный viewport и убедиться, что добавление и drag-and-drop доступны без горизонтальной прокрутки страницы.
- Обновить пользовательское описание календаря, если оно есть.
- Следовать проектному циклу проверок: `pnpm test`, `pnpm test:e2e` и `pnpm build`; устранить регрессии перед выпуском.

## Основные риски

- **Конфликт кликов и перетаскивания:** запускать создание только для клика по пустой области или явной кнопке, не для события карточки.
- **Локальная дата и UTC:** дата ячейки должна сохраниться как тот же календарный день в часовом поясе пользователя.
- **Плотные ячейки:** кнопка добавления не должна перекрывать дату, счётчик или карточки; использовать компактное расположение и доступное имя.
- **Соседние месяцы:** не вычислять дату из номера дня без месяца и года конкретной ячейки.
- **Разные точки создания:** повторно использовать общую форму, чтобы поля, валидация и обновление кэша не расходились.

## Критерии готовности

- Из календарной ячейки можно открыть создание задачи с заранее выбранным днём.
- Новая задача сохраняется и появляется в календаре на выбранной локальной дате.
- Клик по существующей задаче открывает её детали, а drag-and-drop продолжает менять дату.
- Дни соседних месяцев и мобильное взаимодействие работают корректно.
- Отмена не создаёт задачу, а ошибка не теряет введённые данные.
- Основные сценарии создания, кликов и перетаскивания покрыты UI и E2E проверками.
